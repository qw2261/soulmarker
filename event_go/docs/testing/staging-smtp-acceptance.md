# Staging SMTP 验收规程

> 对应：G4-R03 / GATE-G4-SMTP<br>
> 记录位置：`docs/releases/v6.0.0/acceptance/staging-smtp.md`

## 1. 前置条件

- 使用与候选 Commit 绑定的 staging 制品，不直接运行未提交工作树。
- `APP_ENV=staging`，HTTPS `PUBLIC_BASE_URL`、独立 staging 数据库和真实 SMTP 凭证均已配置；证据不得记录密码、JWT、原始一次性 Token。
- 准备一个已知邮箱账户、一个 phone-only 历史账户、一个未注册邮箱和两个独立浏览器会话。
- 验收前记录数据库备份、候选 SHA、部署记录、测试邮箱和执行人；测试邮箱在文档中脱敏。

## 2. 密码重置验收

1. 已知邮箱申请密码重置，页面返回统一成功状态。
2. 邮件在约定时间内到达，From、Subject、HTTPS 域名和有效期正确；记录脱敏邮件头与到达时间。
3. 打开链接并设置新密码；新密码可登录，旧密码不可登录。
4. 申请前已登录的另一个浏览器会话访问受保护页面应返回失效并安全回跳。
5. 同一链接再次使用必须失败；较早的已被替代链接必须失败。
6. 未注册邮箱申请返回与已知账户相同的页面和 HTTP 状态，且不得收到邮件。

## 3. Phone-only 恢复邮箱验收

1. 使用原手机号和当前密码登录，不改变原 `contact`。
2. 在账户安全页输入真实测试邮箱和当前密码申请绑定；错误密码必须拒绝。
3. 验证邮件到达并指向 staging HTTPS 域名；确认后旧浏览器会话失效。
4. 仍可用原手机号登录；账户安全页显示已验证恢复邮箱。
5. 再次绑定其他邮箱必须按当前产品规则拒绝。
6. 退出后使用恢复邮箱申请密码重置，完成收件、重置和旧会话撤销。

## 4. 失败与隐私检查

- SMTP 暂时不可用时服务端记录可操作错误，客户端仍保持账户枚举安全响应。
- 应用日志、浏览器截图和提交文档不得出现 SMTP 密码、JWT、完整 Token 或未脱敏个人邮箱。
- 检查重复点击、过期链接、大小写规范化和一分钟限流。
- 任一步出现 P0/P1，立即停止 G4 发布并登记到 `defect-register.md`。

## 5. 通过标准

- 所有步骤有时间、执行人、候选 SHA、脱敏截图/邮件头和结果。
- 已知账户成功收件并完成重置；phone-only 账户成功绑定并保留手机号登录；旧会话全部撤销。
- 未知账户不泄露存在性；一次性 Token 不能重复使用。
- 记录由执行人和复核人确认后，方可勾选 G4-R03 的 staging SMTP 验收。
