# 测试策略

> 状态：Active
> 适用版本：v5.2 起
> 路线图来源：[goal.md](../goal.md)

## 1. 目标

测试体系必须证明用户旅程、授权边界、数据一致性、部署和回滚成立，而不是只统计测试函数数量或总覆盖率。

## 2. 测试分层

| 层级 | 目的 | 当前门禁 |
|---|---|---|
| Go 单元/集成 | Handler、Store、业务错误和 SQLite 行为 | 每个 PR |
| Router 集成 | 生产路由、中间件和权限组合 | 每个 PR |
| 前端构建 | TypeScript 与生产打包 | 每个 PR |
| 前端 unit/component | 页面状态和组件交互 | G4 前建立 |
| API 契约 | OpenAPI 与客户端类型一致 | G3 前建立 |
| E2E | 用户和运营完整旅程 | G4 前建立 |
| 安全 | 认证、越权、PII、依赖和 Secret | G1 起持续 |
| 并发/性能 | 容量、库存、核销、支付和 SLO | G2 起持续 |
| 运维 | Docker、迁移、备份恢复和回滚 | G6 前完成 |

## 3. 快速门禁

    gofmt -l ./cmd ./internal
    go test -count=1 ./...
    go vet ./...
    npm ci
    npm run build
    npm test

## 4. 完整门禁

    go test -race -count=1 ./...
    npm run e2e

进入 G4 后，完整门禁还必须包含前端 unit/component 与核心浏览器 E2E；进入 G6 后增加迁移、Docker smoke、备份恢复、安全扫描和性能验证。

### G4 浏览器矩阵

| 项目 | Playwright 设备 | 用途 |
|---|---|---|
| desktop-chromium | Desktop Chrome，1280×720 viewport | 桌面用户与运营完整旅程、键盘入口和失败恢复 |
| mobile-chromium | Pixel 7 | H5 用户与运营完整旅程、移动导航、局部表格滚动和页面级横向溢出检查 |

G4 的每个核心 E2E 必须同时运行两个项目。进入 G6 的公开生产门禁前，矩阵必须增加 macOS Safari/iPhone WebKit 和目标 Android Chrome 真机或等价云设备验证。

## 5. 测试数据

- 单元和普通集成测试使用独立临时数据库。
- 迁移测试必须覆盖空库、上一发布版本数据库、重复执行和失败恢复。
- 安全与 E2E 使用合成身份，不使用真实用户 PII。
- 测试之间不得共享可变状态或依赖执行顺序。

## 6. 缺陷等级

| 等级 | 定义 | 发布规则 |
|---|---|---|
| P0 | 资金、数据丢失、认证绕过、系统不可用 | 立即停止发布 |
| P1 | 核心流程失败、越权、隐私泄露、无法恢复 | 阶段完成前必须关闭 |
| P2 | 非核心功能错误或存在可接受绕行 | 必须记录 Owner 和期限 |
| P3 | 体验、文档或低风险优化 | 进入 Backlog |

## 7. 质量度量

- 当前阶段不使用 covdata，也不以历史覆盖率作为发布门禁。
- 每个风险 Requirement 必须有可追溯的自动化或人工证据。
- 身份、权限、容量、库存、核销、支付、退款和对账按场景全覆盖。
- 若后续重新引入覆盖率，只作为发现盲区的辅助指标，不替代业务验收。
