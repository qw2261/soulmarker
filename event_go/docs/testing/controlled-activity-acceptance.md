# 受控活动验收规程

> 对应：G4 完成门槛 / GATE-G4-UAT<br>
> 记录位置：`docs/releases/v6.0.0/acceptance/controlled-activity-01.md` 与 `controlled-activity-02.md`

## 1. 通用规则

- 两场活动必须是独立事件、独立时间窗口和独立参与者集合；自动化 Playwright 不替代本验收。
- 使用候选 Commit 对应的 staging 或受控部署，操作只能通过用户/运营界面和公开 API，不直接查询或修改数据库来完成业务步骤。
- 每场记录候选 SHA、部署、活动 ID、执行人、参与人数、开始/结束时间、截图、导出文件 SHA-256、日志时间窗和发现的缺陷。
- 真实 PII 不进入 Git；邮箱、手机号、凭证和导出内容必须脱敏，原始证据放受控 Artifact/存储并记录引用。

## 2. 活动一：报名与取消闭环

1. 运营人员登录，创建门店、免费活动和免费票种。
2. 至少两名参与者注册/登录、浏览活动并报名；确认 Admission 二维码和“报名成功”通知。
3. 一名参与者发帖，另一名参与者回复；未报名用户不得发帖或回复。
4. 运营端跨页查看并导出报名；验证 CSV 可打开、无公式执行风险且数据与页面一致。
5. 一名未核销参与者取消报名；库存仅恢复一次、Admission 显示已吊销、取消通知可见。
6. 重复取消不得改变库存或产生重复业务记录。

## 3. 活动二：变更、提醒与履约闭环

1. 创建另一活动并完成至少两名参与者报名。
2. 运营人员修改时间或地点；所有当前参与者收到活动变更通知。
3. 将活动置于提醒窗口并等待调度；每名参与者只收到一条对应计划提醒，重复扫描不重复。
4. 运营人员核销一名参与者；重复扫码返回同一核销结果，审计列表只有一条成功记录。
5. 已核销参与者取消必须被拒绝；未核销参与者仍按截止规则处理。
6. 完成举报、移除/恢复或驳回中的至少一条治理路径，并核对动作审计。

## 4. 每场通过标准

- 全程无人工改库、无身份冒用、无跨活动数据访问、无重复库存/核销记录。
- 核心页面在约定桌面和移动设备可完成，无阻断性横向溢出或不可恢复错误。
- P0/P1 为 0；P2 有 Owner、期限和风险接受记录。
- 执行人与复核人签字，证据引用可访问且与候选 SHA 一致。

两场记录全部通过后，才可勾选“至少完成 2 场内部或受控测试活动”。
