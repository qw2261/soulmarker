# ADR-003：通知渠道与投递语义

> 状态：Accepted
> 日期：2026-07-15
> 适用：D-006 / G4-R05 / Schema v11

## 背景

免费活动可用版需要覆盖报名成功、取消、活动变更和临近提醒。直接把业务通知全部同步发送到 SMTP 会让报名事务受外部服务可用性影响，也无法可靠表示已读、重复投递和历史追溯；短信还涉及地区、成本、模板审核和隐私决策。现有 SMTP 仅用于密码重置与恢复邮箱验证等安全邮件。

## 决策

1. G4 的业务通知事实源为数据库持久化站内通知；用户可查询、分页、查看未读数并标记已读。
2. 报名成功、取消和活动变更通知与对应业务写入同一 SQLite 事务，业务成功时通知必然存在，业务回滚时通知同时回滚。
3. 临近提醒由单实例后台调度器扫描未来 24 小时内的 published 活动，并通过唯一 `idempotency_key` 保证重复扫描不重复创建。
4. 通知保存类型、标题、正文、活动引用、站内跳转、创建时间和已读时间；不复制用户联系方式或 Admission 凭证。
5. 密码重置与恢复邮箱验证继续使用同步 SMTP 安全邮件，不进入普通通知中心，避免把一次性 Token 持久化到可读消息正文。
6. G4 不发送业务短信或业务邮件。G6/G8 如需扩展外部渠道，以站内通知/事务 outbox 为事实源增加异步适配器，不改变业务事务语义。
7. 活动被删除时通知保留，`event_id` 通过 `ON DELETE SET NULL` 解除引用；历史通知不级联丢失。

## 后果

- 用户在无外部邮件供应商时仍能获得完整、可追溯的业务通知。
- 单实例 SQLite 调度器适用于当前 M1；进入多实例部署前必须把提醒调度升级为带租约的单执行者或外部任务系统。
- 站内通知不等于到达率保证；真实业务邮件、短信成本和地区合规仍需在 G6/G8 决策。
- 服务停机跨过整个提醒窗口时无法补发“活动开始前”提醒，运维监控和后续 outbox/调度基础设施需覆盖这一风险。
